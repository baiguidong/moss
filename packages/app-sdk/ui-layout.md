# Moss App 布局与视觉约定

新建、迭代、Skill 转换都按此约定验收。目标是让用户在首屏看到主要输入、数据、编辑器或结果；空间紧凑，同时保留可读性、点击区域和键盘操作。它是 App 作者的布局约定，不是 Host 自动修改页面的机制，不增加 Manifest 字段或最低 Host API。

## 内容与操作的位置

- Moss 已提供 App 名称、简介、迭代、AI 能力和整页刷新，内页从业务内容开始。保留对象、列表和分区名称，避免品牌头部、欢迎横幅、装饰性 Hero 和重复说明。
- 设置、帮助、更多、次要刷新放在现有业务工具栏或分区标题的右侧，不能为了一个设置按钮再增加一行空白头部、一整张卡片或固定高度区域。没有其他工具栏时，直接放入主要内容的标题行；不能添加无意义文字来填满一行。
- 一个区域只保留一个突出主操作。筛选、搜索、计数、状态和相关操作尽量共用一行；窄窗口按实际宽度换行，低频选项放入抽屉、弹层或折叠区。必填配置、阻塞错误和主要操作必须保持可见。
- 列表、表格、编辑器、画布、结果预览使用可用宽高。工作区用 `minmax(0, 1fr)`、`min-width: 0` 和 `min-height: 0` 正确伸缩；不要把整个工作台限制成中间窄卡片。只给长段落或纯阅读内容限制行宽。
- 结果与输入、操作与对象放在相邻区域；宽窗口可并列，窄窗口按任务顺序堆叠。长表格可以在表格内部横向滚动，页面本身不能因固定宽度溢出。避免页面和嵌套卡片出现多层无意义滚动。
- 空状态用简短说明和下一步操作，避免数百像素高的空白占位或大图标。有内容后把空间交给内容；不为保持空状态造型而固定预览、表格或编辑器的高度。不要通过隐藏主要结果、截断必读信息、缩小字号来提高密度。

## 与 Moss 对齐的默认值

下列是普通桌面工作区的起点，按具体任务和输入设备调整，不是要求所有页面相同。

| 项目 | 默认值 |
| --- | --- |
| 页面内边距 | 12–16 px；窄窗口 8–12 px |
| 同一区域内间距 / 区域间距 | 6–8 px / 12–16 px |
| 卡片内边距 | 12–16 px；优先一层边界，避免卡片套卡片 |
| 工具栏 | 通常一行约 36–40 px，按内容增高，不预留空行 |
| 普通控件 / 图标 | 28–32 px 高 / 14–16 px；触摸场景扩大点击区域 |
| 正文 / 辅助文字 / 分区标题 | 13–14 px / 12 px / 14–16 px；不用 10 px 正文换空间 |
| 圆角 / 阴影 | 6–10 px；轻边框，阴影主要用于弹层 |

沿用 Moss 的字体栈、线性图标和语义颜色：`--background`、`--foreground`、`--card`、`--muted-foreground`、`--primary`、`--primary-foreground`、`--border`、`--destructive`、`--ring`。主操作使用主题主色，次要操作使用透明或轻边框按钮；不另造渐变品牌配色、彩色大块或厚重阴影。状态不能只靠颜色区分，图标按钮必须有可访问名称和清楚的焦点样式。

App 页面是独立文档，不会自动继承 Moss 外框的 CSS 变量。随包提供与当前 Moss 一致的浅色/深色 token；通过 SDK client 的 `app.getInfo().appearance` 读取 `themeMode` 和 `cssThemeId`，订阅 `appearance` 事件，处理 `system` 对应的系统主题变化，并在卸载时清理订阅。不要写死浅色，也不要假设 appearance 返回整套 CSS 变量。不要从 Core 私有渲染模块导入组件或样式。

## 创建与验收

App Builder 的 `builder_inspect guidance` 提供 `index.html`、`ui.css`、`theme.css`、`ui.mjs` 作为可改造的工作区模板：工具栏包含业务标题和操作，设置没有独占行，输入与结果在宽窗口并列，结果区占用剩余空间。模板中的业务调用必须替换成目标 App 声明的真实 Action，不得交付占位按钮或伪造结果。

在带实际 Moss 外框的普通窗口（如 1200×800）、窄窗口（如 720×600），以及需要支持的小尺寸下检查：

1. 首屏可见主要内容和下一步操作，顶部没有只放设置的空行；普通单行工具栏后，应尽早进入内容。
2. 主区域随窗口伸缩，结果没有被说明、统计卡片和大留白挤出首屏；长文本、空状态、加载与失败状态都可用。
3. 浅色、深色与系统主题切换正常，没有横向页面溢出、遮挡、过小的点击区域；Tab 焦点、标签和弹层关闭正常。
4. 用 `layout-check.mjs` 的 `assertAppContentLayout(pageOrFrame, manifest)` 检查重复身份；对新模板用 `assertAppWorkspaceLayout(pageOrFrame)` 检查内容起始位置、页面溢出及次要操作独占工具栏。标记正确的主要区域，不用装饰占位通过检查。真实密度、阅读顺序和视觉风格仍需看完整页面。

纯阅读、演示、沉浸式画布等任务可以有合理留白，应围绕主要内容设计；不机械地套用管理面板，也不在 Host 注入全局 CSS 来强制压缩已有 App。
