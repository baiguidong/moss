# App 分类与服务接入

当前接入范围和验证结果见 [接入复查记录](app-connector-migration-review.md)。本页记录 Apps 分类与界面的现行约定。

## 分类规则

Apps 管理页、应用市场和会话资源选择器使用「全部 / 本地应用 / 在线服务」筛选。已安装 Apps 默认显示「全部」，应用市场默认显示「本地应用」。用户切换后的管理页和市场分区分别保存。

| 主要用途 | 分区 |
| --- | --- |
| 处理本地文件、设备或工作区 | 本地应用 |
| 接入云端、内网或自托管业务服务 | 在线服务 |
| 用途暂未核实的旧 App | 在「全部」中保留，不推断为本地或在线 |

分类依据是业务用途，不由 MCP、CLI、技能、页面或执行位置决定。飞书、钉钉、腾讯会议和云客等工具即使通过本地 CLI 执行，仍属于在线服务。数据库 App 同时支持本地和远端数据源，按主要用途归类。一个 App 保留一个稳定身份和主分区，切换配置不会改变分类。

原有办公、开发、自动化、通信等 `category` 用途分类继续作为二级筛选。`featured` 只表示目录推荐。分类、认证方式、启用状态、授权状态和会话选择分别处理。

## 页面与会话

Apps 管理页只显示已安装的 App；应用市场显示可安装目录。两个页面提供名称搜索和「全部 / 本地应用 / 在线服务」筛选。未分类的 App 仍可在「全部」中搜索和管理。

会话资源选择器使用同一 App 分类。普通候选依照现有启用、授权及服务可用性规则展示；已选但后来失效的条目仍可见并可移除。原有子服务选择保留。安装、打开页面、登录或搜索都不会自动把 App 加入会话，也不会改变 `toolScope`。

## 认证与元数据

`discovery.group` 表示主要用途，可为 `local` 或 `online`。在线服务的 `authMethods` 可声明 `none`、`browser`、`api-key`、`credentials` 或 `moss-session`；缺失认证字段不能推断为无需认证。当前是否已授权、缺配置或连接失败由运行时状态决定，不写死到安装包中。

旧签名包不原地改写。过渡期由 Host 的 App ID/版本映射提供分类；新版本在 Manifest 与市场目录中携带一致的发现元数据。安装后的展示以实际安装版本为准，不能用市场最新版本的认证方式覆盖旧安装。

分类本身不授予文件、命令、设备或账号权限，也不决定能力在哪台机器执行。App 安装、权限、凭据与会话选择仍按既有 Host 流程处理。
