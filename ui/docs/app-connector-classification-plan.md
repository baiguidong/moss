# App 分类与服务接入

当前接入范围和验证结果见 [接入复查记录](app-connector-migration-review.md)。本页记录 Apps 分类与界面的现行约定。

## 分类规则

Apps 管理页、应用市场只使用「应用 / 工具」主分区，默认显示「应用」。会话资源选择器按同一交付形态分组。管理页和市场的主分区偏好分别保存，旧全部、本地 / 在线主分区偏好升级为应用。

| 交付形态 | 分区 |
| --- | --- |
| 提供自定义 Moss UI / Backend 的应用工程 | 应用 |
| 声明式 MCP、CLI、Skills 能力包 | 工具 |
| 交付形态暂未核实的旧 App | 在「应用」中保留，不推断为本地或在线 |

MCP / CLI / Skills 是可组合能力，仅作为卡片标签与搜索信息，不提供额外能力筛选，也不复制混合工具的身份或安装。Host 自动生成的设置页不算独立业务 UI。本地 / 在线仅作为标签，不提供下拉筛选；飞书、钉钉等通过本地 CLI 访问的业务仍标注在线。数据库查询等自定义 UI 应用不因使用 MCP 而变成配置型工具。

`category` 按用途细分为沟通协作、文档与知识、文件与存储、设计与音视频、开发工具、数据与分析、自动化、AI 与智能体、销售与客户、营销与电商、金融与投研、经营与财税、人事与招聘、教育与文化、法律与风控、出行与生活、诊断与安全。界面只显示当前分区实际存在的分类；未知第三方才使用「其他」兜底。`featured` 只表示目录推荐。分类、认证方式、启用状态、授权状态和会话选择分别处理。

## 页面与会话

Apps 管理页只显示已安装的 App；应用市场显示可安装目录。两个页面共享「应用 / 工具」主分区与名称搜索，不再显示全部、能力或服务属性下拉筛选。交付形态未知的 App 仍可在「应用」中搜索和管理。用途分类栏保留「全部」以查看当前分区全部用途。

会话资源选择器使用同一 App 分类。普通候选依照现有启用、授权及服务可用性规则展示；已选但后来失效的条目仍可见并可移除。原有子服务选择保留。安装、打开页面、登录或搜索都不会自动把 App 加入会话，也不会改变 `toolScope`。

## 认证与元数据

市场目录的 `discovery.kind` 表示 app / tool，`discovery.capabilities` 保存 mcp / cli / skills 能力标签。Host 从实际安装的 Manifest 推导相同信息；`discovery.group` 继续表示 local / online 服务属性。在线服务的 `authMethods` 可声明 `none`、`browser`、`api-key`、`credentials` 或 `moss-session`；缺失认证字段不能推断为无需认证。当前是否已授权、缺配置或连接失败由运行时状态决定，不写死到安装包中。

旧签名包不原地改写。Host 根据 Manifest 形态识别交付类型，并对已知官方旧用途分类提供按 ID 与原分类限定的展示迁移；只调整显示，不覆盖显式新分类或读取市场最新版认证配置。新增用途分类的运行包要求 Host API >=3.21.0。moss-apps 源码分为 apps 与 tool-apps；工具只维护 app.json 与资源，共享生成器保留现有 MCP / 连接器运行适配器、账号归属与权限。

分类本身不授予文件、命令、设备或账号权限，也不决定能力在哪台机器执行。App 安装、权限、凭据与会话选择仍按既有 Host 流程处理。
