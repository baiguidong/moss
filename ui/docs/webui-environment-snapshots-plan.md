# WebUI 云电脑环境快照规划

日期：2026-10-19。状态：功能已实现，181 首轮真实 Docker / 浏览器与 Server 权限验证通过，正在完成 CI 产物复验与部署。用户在 WebUI 设置中创建当前 Docker 环境快照、查看列表、恢复到当前环境；Desktop 不增加该入口。

本轮确认的约束：创建时由用户选择是否保存数据卷，**默认只保存 Docker 环境**；快照数量及空间上限在 **Server 管理设置**中配置；没有配置或获取不到时使用内置默认值；**没有 Server 也可独立运行**，Server 是可选的集中管理端。

## 1. 快照范围与恢复语义

当前云电脑是一位用户对应一个长期保留的 Docker 容器。系统软件、`/etc` 和 Moss 程序留在容器写层；`/home/moss` 是独立卷，包含项目、会话、用户依赖、配置和凭据。正常登录、停启和程序升级保留原 container ID。

创建弹窗每次默认不勾选“同时备份数据卷”，不沿用上一次勾选结果。两种快照分别定义为：

| 类型 | 创建时保存 | 恢复到当前时 |
| --- | --- | --- |
| Docker 环境快照（默认） | 容器系统层、已安装软件、写层内文件、当时的 Moss 程序及元数据；不归档 HOME 数据卷 | 替换 Docker 环境，继续挂载当前数据卷；数据卷中的项目、聊天和配置不退回快照时间 |
| Docker 环境 + 数据卷 | 上述系统内容，以及同一停机时间点的 HOME 卷归档 | 替换 Docker 环境，并从归档恢复新数据卷；卷内文件、会话和配置一起退回 |

`docker commit` 固定容器系统层，`docker save` 导出镜像；只有用户勾选时才执行 HOME 归档。写层中若存在用户文件，也属于 Docker 环境快照范围，不能把“未选数据卷”解释成不会保存任何用户内容。

类型、`includesDataVolume` 和明确的卷清单写入不可变 manifest。未包含数据卷是合法类型，和“应有卷归档但丢失/损坏”分别处理；不得根据文件缺失猜测类型。恢复按所选快照的固定范围执行，确认框明确显示“保留当前数据卷”或“同时恢复数据卷”。

CPU/内存/PID 限额、账号或本地身份、网关地址、控制凭据及快照策略使用当前部署配置，不随快照退回。快照不包含进程内存、未落盘内容、浏览器 IndexedDB、宿主机内核、未知外部挂载和远端服务数据。自行运行的第三方数据库应先正常停止；不承诺任意数据库的业务事务一致性。

仍采用停机捕获、后台打包：默认只需固定系统层；包含数据卷时等待系统层和卷都捕获完成，再启动原环境、导出镜像并校验。停机时间随所选范围和数据量变化。

## 2. WebUI 设置页面

设置增加“云电脑 → 环境快照”。显示条件是 WebUI 且环境控制器提供 Docker 快照能力，**不能把是否连接 Server 作为开关**。未采用 Docker 的普通 Web Host 仍可运行基本功能，但无法提供 Docker 环境快照，界面说明实际原因。

页面提供：

- 当前环境：运行/维护/恢复状态、Moss 版本、快照占用及生效额度。额度只读；标明使用 Server 配置还是内置默认值。
- 创建快照：名称、备注、“同时备份数据卷”复选框，默认关闭；选择变化后重新估算空间并生成预检结果。不能在后端偷偷升级为包含数据卷。
- 快照列表：名称、时间、类型、Moss 版本、大小、手动/恢复前自动保护、状态、备注；支持详情、恢复到当前和删除。
- 操作进度：准备、停止、保存系统、可选的保存数据、启动、打包校验、完成/失败。能测量的传输显示字节进度，其余只显示阶段。
- 恢复确认：目标快照及类型、数据卷是否会覆盖、进程停止影响、保护范围。取消为默认焦点，Escape/关闭不提交。

关闭设置或浏览器不取消已提交任务，重新登录可查询进度。首版不提供执行中强制取消。正在执行、校验或被恢复任务引用的快照不能删除。

恢复后刷新到相应环境的 UI；旧标签排队请求失效。浏览器原草稿隔离保留为“恢复前草稿”，可手动找回，不自动提交到恢复后的会话。

## 3. Server 可选，控制器负责 Docker 操作

| 部署方式 | 身份与设置 | 快照能力 |
| --- | --- | --- |
| 连接 Server 的云电脑模式 | Server 账号及集中策略；策略缺失或读取失败使用默认值 | 控制器管理用户环境并执行快照 |
| 不连接 Server 的独立 Docker 模式 | 本地认证、持久本地所有者和默认额度 | 同样可创建、列出和恢复快照 |
| 非 Docker 的独立 Web Host | 原有本地认证及基本功能 | 没有可捕获的 Docker 环境，不提供此能力 |

独立模式首版采用单一固定所有者和访问密钥登录，身份独立于密钥持久保存，轮换密钥不能创建另一台空白环境。连接 Server 后可使用统一账号、组织管理及集中限额；不要求独立模式具备这些集中能力。

当前 `cloud/gateway.mjs` 强制要求 Server 认证地址，旧 single Docker 部署也没有环境控制器。这两处需要实际适配：复用控制器，拆分本地/Server 身份提供器，让独立部署能受控接管自己原有的容器和卷，不自动重建或清空。Server 配置读取失败不会把已有 Server 身份自动降级成匿名；本地独立模式有明确的本地身份与认证入口。

快照停止用户 Host，因此任务、确认提交、列表、进度和恢复由 Gateway/环境控制器独立提供。只有控制器接触 Docker socket，普通 Host 和 App 均不获得 Docker 管理权限。

拟新增管理接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/cloud/environment` | 当前身份的环境状态、generation、能力、生效限额及配置来源 |
| `GET /api/cloud/snapshots` | 当前环境快照列表，包含类型 |
| `POST /api/cloud/snapshots/preflight` | 创建/恢复/删除预检，绑定 `includesDataVolume`、额度和确认内容 |
| `POST /api/cloud/snapshots` | 提交创建，`includesDataVolume` 缺省为 `false`，返回持久任务 ID |
| `POST /api/cloud/snapshots/:id/restore` | 按 manifest 范围恢复，绑定预检、环境 generation 和快照 revision |
| `DELETE /api/cloud/snapshots/:id` | 删除未被引用的快照，校验确认内容及 revision |
| `GET /api/cloud/operations/:id` | 获取阶段、结果和失败原因 |

接口从当前认证身份解析环境；拒绝浏览器指定任意容器、卷、镜像、归档路径和 Docker 参数。写入校验 Origin、归属及幂等键。操作主体认证/授权失败仍拒绝，不能套用“读取不到策略时用默认值”来放行权限。

设置使用独立管理 client；另提供控制器直接服务的维护页，例如 `/?window=cloud-environment`。页面资源、认证和任务查询均不依赖用户 Host 或 Server 策略服务在线。账号有效与容器可用分开判断，登录 `ensure()`、自动重连和管理员升级/停机都必须尊重持久维护状态。

## 4. 创建流程

1. **预检**：读取所选范围、generation、现有操作、任务/终端/上传/待确认状态、卷清单和空间；获取 Server 策略或默认值，展示准确影响。勾选数据卷后旧预检失效。
2. **登记与互斥**：先持久化任务和额度预留，再进入环境锁；和恢复/停机/升级互斥，同一幂等键只执行一次。改变范围不能复用原幂等请求。
3. **维护与正常关停**：阻止新业务写入、定时任务和后台自动工作，检查已有工作并落盘。正常忙碌时返回阻塞项，不提供强杀 Agent 的快捷方式；停止整个容器。
4. **捕获**：commit 得到固定镜像。仅 `includesDataVolume=true` 时用可信、限权且不联网的 helper 归档 HOME；默认路径不执行数据卷备份。既不运行快照内入口，也不把归档存进用户 HOME。
5. **恢复原环境**：所选部分均固定后启动原容器并检查健康；原本停止则保持停止。捕获失败也优先恢复原环境，不影响既有快照。
6. **打包发布**：导出镜像并计算摘要；按声明范围校验必需产物，原子发布 `ready` 快照。默认快照无需 HOME 归档；声明包含数据卷但归档缺失的快照不得就绪。

正常创建遇到强制终止、超时或关停异常时，不标记为正常一致快照。快照已经保存、原环境却启动失败时，同时展示“快照可用”和“环境启动失败”。临时文件和镜像可按持久任务记录清理。

## 5. 恢复与回退

“恢复到当前”保持逻辑环境 ID、访问地址、身份和配额，底层 container ID 会变化。数据卷是否替换由快照类型决定。

| 恢复类型 | 卷处理 | 校验及保护 |
| --- | --- | --- |
| 仅 Docker 环境 | 保留并复用当前卷，不解包/回退卷数据 | 对快照程序与当前数据做只读兼容检查；未知或不兼容时阻止，不能自动迁移数据来强行恢复 |
| Docker + 数据卷 | 将归档解包到新卷，原卷保留 | 校验快照程序与同一快照数据；成功后切换新卷 |

具体流程：

1. 验证归属、类型、产物摘要、架构、快照格式和控制协议；本地镜像缓存缺失时从归档加载。检查实际 `/opt/moss` 版本，不只看最初基础镜像的 label。
2. 默认快照的候选容器在维护期只读挂载当前 HOME 进行兼容检查，禁止数据库迁移和用户自动任务；不能偷偷复制或备份数据卷作为默认步骤。只有确认兼容后才复用当前卷启动业务。包含数据卷的快照则解包到新卷，不能覆盖原卷或让归档路径/链接写出新卷。
3. 恢复前保护范围与本次将替换的范围一致并在确认中披露：仅恢复系统就只保存系统保护快照，保留原容器并共享现有卷；恢复系统和数据时才创建包含数据卷的保护快照并保留原卷。不因“自动保护”静默备份用户未选择的数据卷。保护快照也占用 Server/默认额度，缺少所需名额或空间时在执行前提示清理或调整额度。
4. 原容器丢失时，可根据持久环境记录显式恢复已有快照；仅系统快照仍要求当前数据卷存在。只有包含数据卷的快照能够恢复丢失的卷。无法保护当前状态时在确认中说明，不能自动创建空白卷伪装完整恢复。
   容器仍运行但 Host 无响应时，仅允许用包含数据卷的快照恢复。确认中说明可能中断未完成的工作、无法创建一致的自动保护；原容器和原卷不自动清理。执行前若 Host 恢复响应且存在工作，仍拒绝停止。认证或归属错误不能当作 Host 故障绕过。
5. 候选容器以隔离网络、禁止自动重启和恢复校验模式启动；禁止自动会话恢复、定时任务和 App 后台副作用。环境变量、控制凭据、配额和 Docker 配置来自当前受控配置，不能照搬归档里的身份、特权或未知挂载。
6. 检查通过后确保原容器停止，再通过持久 journal 和事务切换 container ID、卷引用、generation 及新控制凭据。仅系统恢复继续引用同一个当前卷；包含数据恢复切换到新卷。
7. 撤销旧 WS、Cookie、OAuth、App 上下文、资源和端口句柄，要求旧页面刷新。历史未完成确认和运行任务不自动复活，外部副作用不重复执行；数据回退后尤其不能补跑历史定时任务。
8. 完成前失败时停止候选环境、恢复原容器及正确的卷引用，分别记录故障和回退结果。仅系统保护没有卷历史副本，不能声称能撤销程序对现有卷产生的写入，因此发布前严格只读检查且不做数据迁移。开放业务后的回退走一次新的显式恢复，不静默丢弃新操作。

成功后原容器最多保留 24 小时供受控回退。仅系统恢复没有一份“旧数据卷”可删除，清理必须识别新旧容器共用的活动卷；任何路径都禁止删除当前引用资源。自动保护快照按同一数量/空间额度计费和管理，不额外绕过上限。

## 6. 一起处理的运行边界

| 边界 | 处理 |
| --- | --- |
| 旧标签自动重发 pending 请求 | Gateway 维护单调递增的 generation，恢复后拒绝旧代际 HTTP 写请求/WS 请求；客户端停止重放并刷新 |
| 数据卷快照退回幂等数据库 | 恢复任务记录在控制器，业务请求同时按 generation 隔离；不能仅依赖卷内 `requests.sqlite` |
| 本地草稿仍来自恢复前 | 按 generation 隔离保留，提供显式查看/合并，不自动回填 |
| 控制器重启或 Docker 调用超时 | 持久 journal 对账资源与阶段；超时不等于操作未发生，不能直接重复执行 |
| 大快照超过临时 drain 时长 | 维护绑定持久任务/续租，Host 重启也先检查恢复锁；不能过期自动放行业务 |
| 登录、升级、停机和恢复并发 | 共用环境锁、租约与 generation；控制器失去租约不能继续切换映射 |
| 没有 Server / 策略获取失败 | 本地模式照常认证；策略回退默认值，仍执行本地额度统计和磁盘检查 |
| 旧 Host 未支持恢复检查或代际协议 | 拒绝该不兼容恢复，原因是协议能力，不能误提示“必须购买/连接 Server” |
| 额外挂载 | 预检列明保存与保留范围。首版只自动管理已登记的 HOME 卷及 Docker 运行时挂载，未知挂载不能静默丢失或被卷选项隐含包含 |
| 凭据与外部数据 | 按实际保存范围保护私有内容，不输出密钥；外部账号撤销、远端数据和已发邮件不随恢复回退 |

容器 ID 不匹配时拒绝普通登录的保护保留；只允许完整恢复 journal 授权一次有记录的替换。独立部署接管既有容器也必须明确核验原容器及 HOME 归属。

## 7. Server 设置、默认值与存储

### 集中设置与回退规则

Server 管理后台“系统设置 → WebUI / 云电脑 → 快照策略”配置数量和空间上限，复用现有 `/api/v1/settings/system` 和 `admin:settings` 写权限。用户 WebUI 只展示生效额度，不能自行修改；Server 不直接拿 Docker socket，执行和用量统计仍归各环境控制器。

拟增加 `webui.snapshots` 设置，初始默认值为：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `maxSnapshotsPerEnvironment` | `5` | 每个环境可保留的快照总数，手动和自动保护均计入；在途创建预留名额 |
| `maxBytesPerEnvironment` | `21474836480`（20 GiB） | 每环境快照存储上限；已确认的内置默认值，可由 Server 管理员修改 |

默认值定义在 Server/控制器共用的轻量契约中，不能两端分别写一套。数据卷默认不选是创建行为，不由额度策略静默改成选中。

生效顺序：成功获取的有效 Server 字段覆盖默认值；未配置、旧 Server 没有字段/接口、超时、网络错误或响应不可用时回退内置默认值。部分字段缺失只回退该字段。策略获取失败时按用户要求使用默认值，不强制沿用历史 Server 缓存，也不阻塞独立运行。读取到非法字段使用默认值，管理员保存非法配置则明确报错。

控制器通过专用的只读策略接口获取非敏感字段，例如 `GET /api/v1/webui/snapshot-policy`；不能把含模型密钥的完整系统设置返回普通用户。独立模式未配置 Server 时直接使用默认值。设置页标明生效数值及来源。

创建预检和提交时刷新生效策略并验证名额/空间。管理员下调后已有快照保留，超额只限制新增，不自动删除；已被接纳的操作保留其额度预留和策略记录，不因网络抖动中途丢弃产物。恢复/删除仍需满足实际执行条件，不能因为超额就把用户彻底锁在无法清理的状态。

达到数量上限时提示清理快照；恢复如果需要新增保护快照，在确认前提示所需名额。不得额外保留“第 6 个自动快照”绕开默认 5 个总量，也不静默删除手动快照腾位置。

### 存储边界

快照存储位于控制器独立持久目录/卷，如 `/snapshots/<environmentId>/<snapshotId>/`，不进入用户 HOME。发布后的 manifest/镜像归档/可选 HOME 归档/摘要不可变。类型与卷清单、实际程序版本、归属、大小、摘要、操作阶段、原/目标资源和策略记录均持久化。

每环境空间核算覆盖保留归档及快照产生的临时产物；节点检查还包括恢复候选卷、受保护旧资源和 Docker 镜像缓存的峰值需求。共用活动卷不能作为新增备份重复计量，未选择数据卷不产生其备份占用。不能只检查额度而忽略真实磁盘剩余；中途写满保留原环境并清理未发布产物。

快照目录、Docker socket 和实际存储挂载属于部署基础配置；业务数量/空间策略在 Server 设置或内置默认值中生效，不要求为了默认额度搭建 Server。同节点快照不等于异地备份，控制器状态/installation ID 仍需另行备份。

## 8. 分批实施与验收

| 批次 | 实施范围 | 完成条件 |
| --- | --- | --- |
| A：独立运行与管理 | 可选 Server、独立身份/本地认证、既有 Docker 环境受控接管、持久任务、维护页、Server 策略设置及默认回退 | 无 Server 可直接运行；策略读取失败可用默认值；Host 停机后列表和管理仍可访问 |
| B：创建与列表 | 默认系统快照、可选卷归档、范围绑定、校验、额度、列表/删除 | 未勾选不备份卷，勾选后包含卷；两种类型均可正确发布，半成品不得就绪 |
| C：两类恢复 | 当前卷保留/新卷恢复、兼容检查、范围一致的保护、映射 journal、generation、回退和清理 | 仅系统恢复保留当前卷；带数据恢复退回卷；所有权、旧请求及错误回退行为正确 |
| D：review 与故障演练 | 真实 Docker、双用户、多标签、断线、容量及崩溃测试；修复发现的问题 | 以下核心验收通过后开放生产恢复 |

核心验收：

1. 无 Server 的独立 Docker 部署可登录并创建、列出、恢复快照；接入 Server 后管理员策略生效；未配置、单字段缺失、404、超时、非法响应时按规则回退 5 个/20 GiB，本地用量不被重置。
2. 默认创建只包含系统镜像；随后修改系统和 HOME，恢复后系统退回、HOME 保留最新文件/会话/配置；整个流程不生成数据卷快照。当前卷丢失或程序/数据不兼容时明确拒绝，不能创建空白卷顶替。
3. 勾选数据卷创建另一快照，随后新增/修改/删除系统与卷内内容；恢复后所选两部分同时退回，数据权限和实际 Moss 程序匹配；恢复前保护快照范围正确。
4. 数量/字节上限、并发预留和自动保护共同生效；恢复前额外空间不足在切换前拦截；管理员降低额度不自动删快照，删除可用于解除超额。
5. 多用户不能枚举或操作他人快照，App 页面没有管理权限；Server 不可用不能造成匿名接管现有 Server 用户环境。
6. 多标签重复提交只执行一次；创建范围变化必须重新预检；刷新/关闭后仍能查询；恢复后旧 pending 请求、上传、编辑保存和资源链接失效。
7. 检查损坏归档、声明带卷但文件缺失、错误架构、额外挂载、Host 故障、镜像缓存删除、原容器/卷丢失等场景，没有空白环境伪装恢复成功。
8. 在停止、捕获、解包、候选启动和映射切换前后中断控制器/Docker；恢复后只有一个活动环境，旧卷和共用当前卷不被误删，候选实例不提前执行外部副作用。
9. 整体 review 检查临时归档、镜像、候选容器/网络、保护快照、控制凭据、额度预留和任务记录的完整生命周期。

## 9. 代码落点

- `server/src/systemSettings.ts`、`server/src/server.ts`：可选的集中快照策略及专用非敏感读取接口。
- `admin/src/pages/system-settings-page.tsx`、`admin/lib/api/settings.ts`、`admin/lib/api/types.ts`：Server 管理设置中的数量/空间配置。
- 共享轻量快照策略契约（新增）：字段、默认 5 个/20 GiB、校验与回退，供 Server/控制器共用。
- `cloud/snapshots.mjs`、`cloud/snapshot-store.mjs`（新增）：两类快照、任务、额度和恢复状态机。
- `cloud/gateway.mjs`：可选 Server 身份提供器、本地认证、管理接口/页面、策略读取回退、代际校验与连接撤销。
- `cloud/environments.mjs`、`cloud/store.mjs`：稳定本地身份、既有环境接管、HOME 引用、generation、恢复 journal 和互斥。
- `cloud/docker.mjs`：系统 commit/save/load、可选卷归档、受控候选及资源清理。
- `ui/src/web/auth.mjs`、`ui/src/web/lifecycle.mjs`、`ui/src/main.mjs`、`docker/webui/entrypoint.sh`：本地认证衔接、关停准备、只读兼容检查和恢复检查模式。
- `ui/src/client/web-transport.mjs`、`ui/src/renderer-react/web-bootstrap.ts`、草稿模块：旧请求停止重放、刷新与草稿隔离。
- `ui/src/renderer-react/components/settings-view.tsx` 与新快照面板：范围复选框默认关闭、类型/额度展示、独立维护页面。
- `deploy/webui/compose.yaml`、`deploy/server/compose.yaml` 与部署脚本：独立/Server 两种部署的环境控制器及快照存储，保留原容器/卷。

本规划保留手动快照与恢复首版范围，不扩展定时快照、公开镜像导出、跨用户克隆、跨机恢复和 VM 内存快照。实现结束后继续整体 review、修复与恢复演练。
