# WebUI / Desktop 适配方案与完成状态

基于 [2026-10-16 源码审计与验证记录](webui-desktop-adaptation-audit-20261016.md)。A、B、C 批次的本地实现、review 和修复已完成；完整云端远程浏览器继续按约定暂缓。本文保留设计约束，实际交付范围、验证证据及部署前提以审计记录为准。尚未部署。

## 1. 能力契约与执行位置

扩展 Host 启动状态和 Web 握手快照，提供带版本的能力清单，按功能返回是否支持、不可用原因和替代操作。前端用它决定入口，Host 继续独立验证每次调用。

需要分别表达：

- 界面：Desktop / WebUI。
- 执行位置：当前 Host / remote-direct；Web 下当前 Host 通常是云电脑。
- 资源位置：浏览器设备 / Host 文件系统 / 远程工作区 / App 资源。

能力至少覆盖文件浏览、上传下载、确认请求、OAuth、App 页面、预览窗口、终端、云电脑端口预览、桌面控制和更新。不要再用方法是否存在判断支持状态。现有 `isWebUI()` 只识别界面类型，后续入口逐步改为查询具体能力。

实现落点：`ui/src/shared/host-capabilities.mjs`、`ui/src/client`、`main.mjs:getBootStatus`、`web/server.mjs`、各 renderer 入口。当前能力契约提供版本、模式及功能开关；不可用原因由各入口显示。

完成条件：同一功能在 Desktop、Web、旧版 Host、能力缺失时均有明确行为；入口展示与 Host 支持情况一致。

## 2. 共用确认服务，分别展示弹窗

复用 `decision-broker.mjs` 和数据库原子认领，补充结构化确认请求及详情查询。业务服务负责生成确认内容与执行动作；Desktop 使用原生对话框，Web 使用页面内弹窗。现有会话工具权限卡继续使用原有交互。

确认请求绑定操作 ID、用户/Host、请求方、目标会话或 App、操作类型、完整披露内容、目标 revision/安装包摘要、有效期和允许的选项。通知只负责提醒和入口，完整授权内容单独获取，避免通知截断影响审阅。密钥和 OAuth verifier 不进入展示数据。

| 场景 | 确定行为 |
| --- | --- |
| 在页面主动发起安装等操作 | 在发起页面显示确认；其他标签显示待办提示，可主动打开 |
| 后台产生确认、发起页已关闭 | 保留待确认项，其他已登录页面可查看处理 |
| 多标签同时处理 | Host 只接受第一笔有效决定，其他页面同步完成状态 |
| 点击取消 / 关闭阻塞确认弹窗 / Escape | 取消该操作；“稍后处理”如提供，必须是单独按钮 |
| 关闭通知中心、临时断线 | 保留待确认状态，不视为同意或拒绝 |
| 超时、任务停止、目标删除 | 请求失效，唤醒等待中的调用并返回明确取消原因 |
| 刷新 / 重连 | 拉取权威待办状态，不仅依赖事件重放 |
| 目标在确认期间发生变化 | revision/摘要不一致则停止，重新生成确认内容 |
| Host 重启 | 当前仅有内存执行回调的请求过期；只有实现操作日志及结果核对的业务才能恢复，不能自动重试未知结果的写入 |

显示在哪个标签只决定弹窗位置，不能作为授权凭据。App iframe 无权调用主页面的决策接口。新增确认类别应明确可接受的响应渠道，避免只看到摘要的渠道批准必须审阅完整详情的变更。

### 安装和创作授权

从 `app-tool-disclosure.mjs` 提取共用披露数据，包括 App 身份、新增权限、工具效果、skills、市场版本替换和原生适配器说明。

安装拆成“选择文件 → 准备并验证安装包 → 确认 → 再次校验 → 提交”。Desktop 使用原生选择器；Web 复用云电脑文件浏览或本机 ZIP 上传。Host 对待安装内容暂存并绑定摘要，提交时复核安装状态及 grants。市场安装、ZIP 安装、创作安装都接入同一确认服务，避免遗漏非页面入口。创作页面预览还依赖第 5 节的 App 页面适配。

### App 修改配置和证书变化

`moss-settings-service.mjs` 继续负责脱敏、revision 校验、取消检查和回执；将 Web 分支的直接报错替换为等待确认。用户看到修改目标和前后差异，批准后继续原操作。

证书变化使用同一服务展示服务器地址和旧/新指纹。Host 接受证书与用户浏览器信任证书是两件事；Web 页面不能代替浏览器关闭证书校验。

完成条件：真实安装/配置修改必须先展示对应内容；拒绝、超时、跨标签重复响应和确认期间目标变化都不能执行变更。

## 3. OAuth：浏览器授权，Host 保存凭据

抽离现有 OAuth 的回调接收器：Desktop 保留 loopback listener，Web 使用固定 HTTPS 回调端点。Host 生成并保存事务、state、PKCE verifier 和有效期；用户浏览器完成登录；回调将授权码交给所属 Host 校验和交换，凭据继续保存在 Host。

已同时处理以下两个依赖：

1. [server/src/auth/oauth.ts](../../server/src/auth/oauth.ts) 现通过 `requireOAuthRedirectUri` 接受 `MOSS_OAUTH_WEB_CALLBACKS` 精确配置的 HTTPS URL，同时保留 Desktop loopback 规则。未放开任意 `redirect_uri`。
2. [cloud/gateway.mjs](../../cloud/gateway.mjs) 使用 `SameSite=Strict` Cookie 按登录态路由；OAuth 从外站返回时不能依赖该 Cookie 找到云电脑。新增专用回调路由，通过预先登记的一次性随机事务标识映射到用户/Host，再由 Host 验证 state、提供方和 PKCE。该例外仅接收授权回调，不能成为通用匿名代理。

具体流程：

1. 用户点击登录时同步预留浏览器页面；若来自 Agent 后台请求，则给用户可点击的授权按钮。
2. Host 返回经过校验的授权 URL，事务绑定连接器/目标 Server、发起用户和 Host。
3. 回调端点接收结果并由 Host 交换授权码；重复、已取消和过期回调不能再次交换。
4. Web 通过事务状态更新显示成功、拒绝、取消或超时。刷新后可恢复状态；同一连接器的重复发起应返回已有事务或明确取消旧事务。
5. 关闭弹窗但仍有主页面时尝试取消；页面全部消失时由事务有效期兜底。不能靠浏览器关闭事件保证取消一定送达。

MCP 标准 OAuth、连接器自定义登录、Moss Server 登录分别接入事务服务。第三方提供方若只允许 loopback、需要读取跨域页面 Cookie，或没有可用的 Web 回调注册，须做提供方适配；支持的情况下提供设备码或手动凭据方式，不能假定所有提供方可直接套用同一回调。

完成条件：公网回调经云网关回到正确 Host；无登录 Cookie 的合法回调可完成；错误 state、重复回调、取消后回调、浏览器刷新和多标签发起均有明确结果。

## 4. 文件预览、独立页面与下载

保留共用 presentation 和文件读取服务，增加 Web 展示适配：

- 有会话的文件/App 资源，统一通过 presentation 打开；没有会话的附件使用只读预览句柄，不创建虚假会话。
- 独立窗口改为可刷新的 Web 预览页面，URL 引用经过授权的资源句柄；编辑仍使用现有 ownership 服务。
- HTML 使用包含真实路径层级的资源地址，例如 `preview/<handle>/files/...`，使图片、CSS、脚本可相对定位。句柄绑定用户/Host/工作区或 App，Host 验证路径、符号链接及边界；远端资源通过对应远端服务读取。
- 可执行 HTML 在隔离的预览环境中展示，不能通过同源身份访问主页面的管理接口；不直接取消现有 `/api/files` 的 sandbox 和附件响应保护。
- App 资源链接先解析权限和资源身份，再预览或下载。
- 下载统一走浏览器下载；“用系统应用打开”在 Web 显示为“下载文件”。日志导出也返回可下载文件。
- 外链通过直接点击或同步预留页面打开，异步结果不能一律宣称弹窗已打开。使用 `noopener` 时不能单凭返回 `null` 判定拦截。

完成条件：无会话附件、App 资源、远端 PDF/Office、带相对图片/CSS 的 HTML、独立页面刷新均可用，且资源句柄不能访问其他用户或越出授权目录。

## 5. App 页面和云电脑网页

### App 页面

实现浏览器版 App SDK 传输，复用 App Runtime 的权限和调用逻辑：

- Desktop 保留 webview/preload；Web 使用隔离来源的 iframe。
- Host 创建绑定 App、实例、用户、版本和页面生命周期的访问上下文，App 不能自己声明或切换身份。
- 父页面经校验的 MessageChannel 转发受限 SDK 请求；iframe 不获得 `agentDesktop` 或主页面 Cookie。
- 保留现有请求取消、并发限制和事件订阅语义；页面关闭、导航、App 禁用或卸载时撤销上下文。
- App 静态文件在隔离来源加载；不能仅把同源网页加上同时允许 scripts 与 same-origin 的 sandbox 就视为完成隔离。
- App 设置页、工作台、小组件和创作预览共同使用这一适配，避免各自维护桥接。

文件选择、下载、摄像头、麦克风、截图分别声明目标位置：浏览器设备由浏览器权限管理；云电脑资源由 Host 权限管理。浏览器摄像头授权不等于允许采集云电脑设备，反之亦然。

### 云电脑网页

先提供按用户/Host/端口隔离的预览代理，支持 HTTP、重定向和开发服务器 WebSocket，不能把 `localhost` 原样交给用户设备。普通公网链接在用户浏览器打开。

需要保留“Agent 控制云电脑浏览器”的完整能力时，抽取浏览器服务接口：Desktop 使用现有 Electron 实现，云端使用独立 Chromium 会话及远程视图。第三方网站可能禁止 iframe；端口预览代理不等于完整远程浏览器。

完成条件：App 页面无法调用未授权能力或冒充其他 App；导航/关闭后旧请求失效；云电脑开发页面和 WebSocket 访问正确；浏览器设备与云电脑设备的权限提示清晰。
