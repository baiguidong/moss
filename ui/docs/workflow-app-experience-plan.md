# Workflow App 交互调整计划

状态：六项交互调整已实施，已安装 `moss.workflow@0.1.9`，配套 Host API / SDK / Runtime `2.8.0`。更新：2026-10-09。实际验证范围见第 10 节；下方保留设计决策与验收目标，未执行的故障组合不算通过。

本轮用户明确取消旧 Workflow 兼容要求。本计划覆盖原拆分计划中关于旧数据迁移、人工编辑器、模板入口和运行呈现的要求；0.1.6 的验证记录保留为历史事实。P0–P4 已完成，P5 已完成本地构建、真实包安装和主要 CDP 路径，完整故障矩阵另列验证限制。

## 1. 产品定位与结论

普通会话承接需求描述、Agent 创建/修改、运行输入补全和结果追问。Workflow App 负责定义保存、目录管理、执行调度、流程预览与运行详情。

用户使用一套“选择工作流 → 描述任务 → 在会话中执行”的路径。创建和修改通过 Agent 完成；App 不再提供面向人的 JSON 工作台。Core 仍只负责通用会话、工具权限、任务与 App 容器，流程规则及画布归 App。

## 2. 对六项意见的取舍

| 意见 | 判断 | 处理方式 |
| --- | --- | --- |
| 迁移历史不需要 | 同意，原兼容目标已取消 | 移除迁移页、history Actions、自动扫描/导入以及相关旧入口代理。App 自身的运行记录保留。去掉旧格式兼容不等于重写已复用的 v3 引擎。 |
| 不让用户手工新建、编辑，取消深度研究模板 | 同意，创建能力继续存在于 Agent 工具 | 删除 JSON 编辑器、新建示例、模板卡片和产品侧模板操作；保留轻量“在会话中创建”，编辑改为“在会话中修改”。打开普通会话草稿并准备所需工具及上下文。 |
| 输入框上方大任务卡片不需要 | 同意，但停止入口和最终结果仍需可达 | 使用会话左侧“流程”面板，嵌入 App 专用流程视图。聊天显示一次简洁结果/产物，输入框上方不再展示 Workflow 的名称、时长、状态、链接、结果整块卡片。其他后台任务不受影响。 |
| 新会话中快捷选择工作流 | “选择资源”作主入口，@ 作同源快捷入口 | 两者共用列表、搜索、选中状态和行为，新增“工作流”分组。首次使用更容易发现按钮，熟练用户可用 @。 |
| 两个运行按钮及 JSON 输入不友好 | 建议把 App 内的运行输入区整体收回普通会话 | 已发布流程只留“使用工作流”，跳转会话预选该流程；草稿显示“继续完善”。用户自然语言描述，Agent 按 Schema 生成参数、只追问缺少的必填项。 |
| App 标题、说明、刷新重复 | 同意 | 页面外壳由 Moss 提供；App 内容区移除品牌标题、副标题和重复刷新。详情保留业务工作流名称，状态由事件自动更新；刷新作为宿主恢复操作。 |

移除兼容代码时不清空用户文件。旧迁移历史不再读取或展示；当前 App 定义及运行数据不因移除迁移器而误删。没有业务入口引用的旧代码再删除，通用权限、取消、预算、结果分块和去重继续保留。

## 3. 三条操作路径

### 创建/修改

1. 在普通会话直接描述需要的流程；或者从 App 的“在会话中创建/修改”进入。
2. Moss 打开普通会话草稿，准备 Workflow 创作工具；修改时带上 workflowId、当前修订及来源工作区。界面展示人能理解的名称与需求提示，技术字段由结构化上下文携带。
3. 用户发送需求后才开始 Agent 工作。跳转、选择、预填本身不执行工具，也不持久创建空会话；优先复用空的普通会话草稿。
4. Agent 创建/修改并保存；左侧可预览定义。需要调整时继续用自然语言说明。
5. 保存、发布和执行保持独立。明确要求可重复使用/发布时才发布；要求试跑时 Agent 使用测试操作，不因保存草稿自行执行。

“准备工具”必须真正进入当前轮的工具可用性/发现流程，仅在输入框里写出工具名称不算完成。准备不扩大安装 grants，不修改用户权限模式，也不把所有工具永久加入每个会话。

### 使用已有流程

1. 在首页或现有普通会话，通过“选择资源 → 工作流”或 @ 选择；App 中的“使用工作流”进入同一个选择状态。
2. 输入框显示可移除的工作流标记，例如“市场调研”，并给出与该流程有关的输入提示。
3. 用户直接描述：“研究国内 AI 编程工具，使用这两份资料，输出竞品对比报告。”不展示 `args`、`value`、revision 或 JSON 输入框。
4. Agent 读取参数合同和当前输入，使用明确默认值，必要时通过现有提问交互补齐必填信息。参数经过校验后只提交一次运行。
5. 第一次发送时建立普通会话并绑定工作区；已有会话沿用原会话。提交成功后清除本次选择标记，工作流与运行引用进入消息记录，后续追问不会再次运行。

选择代表带入工作流引用，不等于授权立即执行。用户若问“这个流程做什么”，Agent 应读取解释；只有明确使用/运行请求才启动。App 的“使用工作流”预填使用意图，但仍由用户发送。

选择器默认展示可使用的已发布流程，草稿通过 App 或创作会话管理。选中的定义版本需要固定，发送前重新验证可用性；若该版本已撤下或发生变化，明确提示重新选择，不静默切换。新建会话尚无 sessionId 时，也要根据已选工作区列出个人/项目流程，不能沿用当前斜杠菜单“必须已有会话”的限制。

### 查看运行

- 启动后在会话左侧“流程”面板显示当前运行；用户收起后，后续事件不强制重新展开。
- 面板展示流程图、当前节点、必要的节点结果和停止操作；点击节点查看业务说明、输入/输出、失败原因。
- 同一会话存在多个运行时可以切换，明确区分“定义预览”和“本次运行”，不总是读取全局最新运行。
- 收起面板时，会话栏保留紧凑的流程入口及运行状态；即使主 Agent 已回复结束，仍能找到停止按钮。
- 完成后聊天保留一次结果摘要或产物，支持继续追问；完整结果和运行记录在 App 中可查。去掉重复呈现，不去掉结果账本或追问上下文。
- 窄窗口用可展开的流程抽屉/全宽面板，聊天与流程相互切换，不横向挤压两者。

## 4. 图放在哪里，是否容易实现

推荐“左侧面板作为位置，App 轻量流程页作为内容”。两项需求可以一起满足。

| 做法 | 代价与问题 | 结论 |
| --- | --- | --- |
| Core 再原生绘制一套 Workflow 图 | 会重新引入业务图类型与渲染耦合，需要同步维护两套展示 | 不采用 |
| 每条聊天消息嵌入整个 App | 重复目录/标题/导航，消息列表内多个 webview 成本高，滚动和生命周期复杂 | 不采用 |
| 一个会话面板嵌入 App 专用流程页 | 可复用现有 webview/路由/权限；需要新增紧凑模式、会话绑定和节点状态快照 | 推荐，工作量中等 |

实施前，`embedded-app-view.tsx` 总会渲染宿主标题栏，聊天 WorkflowWorkbench 只识别旧 `kind=workflow`。现已增加紧凑嵌入与绑定来源会话的 App 流程容器，移除旧 Workbench 的实时挂接，不更改新任务的 `kind=app`。

具体改动：

- App 提供定义预览和运行详情两种轻量路由，隐藏自己的目录、品牌栏与调试字段，复用同一画布组件。
- Core 为会话侧栏增加通用 App 容器，可省略重复外壳；只接收 App 身份、任务/资源引用和本地路由。
- 来源会话由 Host 绑定，App 输入不能伪造会话、工作区或权限。关闭视图只销毁 UI，不停止 Backend。
- 仅在可见时挂载一个当前视图；状态更新不重新创建 webview，不给每个节点/消息创建独立实例。
- 先接好面板、停止入口与结果展示，再移除 Workflow 的输入框上方卡片。

运行态数据已补齐：`run.get` 返回持久节点/边状态快照及序号；详细事件写入独立 NDJSON 文件并分页读取。最近事件预览仍有上限，画布以快照恢复全部根流程节点状态。嵌套流程内部事件不混入父图；父节点继续展示它的整体状态。

## 5. @ 与资源选择的实现范围

现有 `composer-mentions.ts` 的资源类型、`MentionMenu` 与 `ComposerResourceSelectionArea` 已有共用基础。应增加同一份工作流选择状态，两个入口调用同一个选择处理器。

App 提供有界、可分页的列表/搜索/预览引用，Core 展示名称、说明和选中状态。列表内容与发布规则仍由 App 决定。优先复用现有贡献、Actions 和命令发现代码，补足资源列表所需字段；现有 resourceProviders 只有 URI 解析，不能直接当作已经具备列表搜索接口。

只补本次需要的能力：App 资源发现、普通会话预填和工具准备、轻量嵌入。保留现有 6 个 AI 工具，不按 UI 按钮再增加 AI 工具。UI 内部 Actions 可以调整或减少。

本次选择先支持一个工作流；多个运行可以存在于同一会话。不要把“同时选多个资源”直接定义成并行执行多个工作流。@ 与“选择资源”本身不启动任何任务。

## 6. 输入与版本的呈现

首版采用自然语言会话输入，不开发一个覆盖任意 JSON Schema 的通用表单编辑器。已有提问控件足以承接缺少的字符串、数字、枚举和文件选择。确实复杂的输入也通过 Agent 整理，用户能看到业务含义。

创建工具的指引需要求 Start 输入提供清楚的 title、description、示例和适用的默认值。例如研究流程询问“研究主题”和“参考资料”，不能统一显示无含义的 `value`。Schema 与后端校验继续使用。

UI 只保留一个主要使用动作。内部继续区分保存的草稿和已发布快照，避免把两个按钮合并成“悄悄发布并运行”。草稿的“继续完善”回到 Agent 创作会话；用户在会话中明确要求试跑时，工具可以测试草稿。

运行中的停止/恢复属于运行控制，仍放在流程面板。发布、归档、删除、导出等低频管理操作收进菜单；版本和技术诊断收进详情，不占用主操作区。

## 8. 验收

- App 看不到迁移历史、深度研究等内置模板、JSON 编辑器、原始参数文本域、两个并列运行按钮和重复品牌头部。
- App 的创建/修改入口进入普通会话，工具在首次请求中就绪，未发送不调用 Agent、不启动任务。
- 新会话没有 sessionId 时，也能通过 @ 和资源选择找到同一份已发布流程；选中并描述任务后只创建一个普通会话与一个运行。
- 修改流程只生成修订；询问流程用途只读取；明确试跑/运行才执行。发送后的版本选择不会静默变化。
- 左侧流程能展示完整节点状态，覆盖超过 10 条事件、分支、循环、并行、foreach、失败、停止、恢复和切换多个运行。
- 关闭/重新打开流程视图、重新进入会话后状态正确；用户收起侧栏不被进度事件反复打断。
- 输入框上方没有 Workflow 大卡片；聊天只有一次最终结果；追问仍能读取结果；其他 App/Bash 后台任务展示不受影响。
- 浅/深色、窄窗口、会话切换和 webview 生命周期无重复外壳、明显卡顿或 renderer error。
- 停用/卸载 App 后资源入口和视图状态正确，不退回旧 Workflow 引擎；已有通用权限/去重/结果大小限制不退化。
- CDP 优先使用隔离数据；清理本轮创建的测试工作流和会话，避免 `CDP · …` 混入正常目录与快捷选择。

## 9. 主要改动位置

- App：`moss-apps/apps/workflow/src/main.tsx`、`src/ui/`、`src/backend/main.ts`、`runs.ts`、Manifest 与 Schema 生成脚本。
- Core 展示：`components/embedded-app-view.tsx`、`components/chat-area.tsx`、`components/chat/message-list.tsx`、`App.tsx`。
- Core 选择：`lib/composer-mentions.ts`、`components/composer-resource-selection-area.tsx` 和 MentionMenu。
- Host/SDK：现有 App preload/IPC、贡献发现、普通会话草稿及工具准备路径；新增字段只表达通用资源与呈现，不包含工作流图规则。

保留现有引擎、后台调度、真实 Agent 执行和通用任务账本。本轮主要重整用户入口、展示与无需保留的兼容面。


## 10. 实施复核与证据（0.1.9）

### 已交付

- 创建、修改、使用均进入普通会话草稿；发送时才创建会话、开始 Agent。工作流引用随草稿保存，App 跳转不再被旧草稿恢复逻辑清空。
- `resourceProviders.listAction`、`composer.prepare` 和按轮工具准备为通用 Host 能力。Core 绑定来源会话/工作区、验证 App 工具归属与授权，不解释流程节点。资源按钮与 @ 共用分页列表、搜索与单个选择状态。
- 仍为 6 个 AI 工具；创建准备 read/create，修改准备 read/edit，使用准备 read/run。迁移、模板与动态斜杠命令贡献已移除，没有按 UI 操作增加模型工具。
- App 内只读目录/画布、自然语言会话入口和低频管理菜单。已发布流程为“使用工作流”，草稿为“继续完善”；不存在 JSON 编辑/输入、两个运行按钮和重复品牌头部。
- 会话左侧嵌入一个 App 轻量流程页，支持定义/运行切换、收起、停止、节点详情和窄屏展开。Workflow 大卡片已退出输入框上方，结果写入普通会话并供后续追问。
- 复用 v3 定义、编译器、状态机、绑定、Journal；新增节点观察、持久状态快照和分页事件，未重写引擎。原分叉图标/提示与复制后时间改动保持。
