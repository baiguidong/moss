# App 子服务选择

Host API / SDK / Runtime 3.8.0。MCP 管理 0.1.10 是首个使用方；宿主没有根据 App ID 判断选择方式的特例。

## 契约

App 根级 `toolSelection` 可为 `app` 或 `services`，省略时保持整体 App 选择。显式声明需要最低 Host API 3.8.0，防止旧宿主忽略服务隔离。普通 App 不因 MCP 服务数量变化而改变选择行为。

原生工具在 `contributes.services` 声明 `{ id, title, description? }`，工具条目通过 `serviceId` 引用服务；services 模式下每个原生工具必须有合法引用。服务 id 在 App 内稳定，标题可以修改。MCP 服务由 Host 自动投影为动态子项，任意声明该模式的 App 都可使用，客户追加服务不必修改或重新构建 App。一个 App 可以同时提供原生服务和 MCP 服务。

MCP 配置的 `id` 是持久化 UUID，编辑、凭据更新和改名保留，删除重建生成新值；旧配置读取时原子补齐。对外服务标识包含 MCP 实例和 UUID。会话使用 `appServiceKey(appId, serviceId)`，不依赖展示名称、工具名前缀或凭据版本。

## 交互

- @ 和资源选择器使用同一个候选投影和选择状态。普通 App 点击即选；services App 显示已选数和展开箭头，点击进入第二层。
- 子服务独立多选，可返回父层；@ 的右箭头可展开当前父项，左箭头或 Escape 返回父层。搜索跨层命中子服务，标签展示 App 与服务名称，可单独移除。
- 全选保存当前可用服务的具体集合，不保存父 App 或未来服务的通配条件。后续新增服务保持未选中。
- 不可用条目不进入 @ 候选；已选服务在资源选择器和标签中可见、可移除。删除重建不会重新激活旧选择。

## 会话与执行

会话新增 `appServiceIds`，独立于原有 `appIds`；草稿、创建、更新、SQLite、元数据文件、恢复、复制及 worker 派生均携带此集合。旧会话对 services App 的整体选择在首次打开或恢复运行时迁移为当时已有服务的固定集合。显式资源自动加入父 App 时，也转换成当前服务集合；不会在后续每轮自动加入新增服务。

服务选择由 Main 校验 App 归属、声明、安装启用和工具可用性。更新串行合并，服务全选只替换目标 App 的子集合，保留其他 App 的选择。忙碌运行保留本轮策略快照，下次安全启动重建。

`toolScope` 保持 App 级：session 只连接、加载已选子服务；global 仍按需发现全部可用服务，只有已选服务常驻。因此“新增不自动选中”不改变显式 global 的按需可见性。服务选择不覆盖安装、实例、授权或工具禁用状态。

原生工具在读取 Schema 前按服务过滤，调用检查再次核对选择。MCP 在连接前按服务过滤，工具策略据真实来源设置常驻状态。ToolSearch 的原生工具按子服务展开，MCP 沿用单服务分组；历史发现和子任务只能使用过滤后的工具池。

## 创建和兼容

Builder 创建指引与随包 README 已加入选择模式、服务引用、稳定 ID、旧 SDK 升级及源码恢复验证规则。普通编辑保留选择模式和服务 ID。Git、文件系统及其他未声明 services 的 App 保持整体选择。

MCP 管理要求 `hostApi: "^3.8.0"`。已有安装需要更新 Desktop 和 MCP App 才会使用新界面；源码修改不会替换已安装签名包。

## 验证入口

- `app-subservices.test.ts`：契约、原生/MCP 混合候选、跨层搜索、服务隔离、串行更新、跨 App 校验及旧选择迁移。
- `app-mcp-host.test.ts`：真实持久化配置、稳定 ID、改名/重启、删除重建、新增服务与启停。
- `session-persistence.node.mjs`：真实 SQLite 和元数据文件重启恢复服务选择。
- `ToolSearchTool.groups.test.ts`：同一 App 原生子服务之间的工具展开隔离。
- `app-subservices.electron.mjs`：实际 Composer 与资源弹窗、键盘导航、搜索、标签、全选后追加服务及会话隔离。`app-tool-selection.electron.mjs` 保留普通 App 的回归。
