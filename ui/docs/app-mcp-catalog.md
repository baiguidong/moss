# App MCP 工具清单与连接状态

2026-10-19。

App 卡片里的 AI 能力是工具清单摘要；“运行中”是 App Backend 的状态。两者独立。旧的“MCP 工具待发现”表示当前进程还没有清单，不代表工具不可用，也不要求用户先手动刷新才能调用。

## 显示与刷新

- 没有清单时显示“AI 能力”，第一次打开能力入口可自动获取；真实失败、授权缺失、停用仍分别提示。
- 成功获取后，在实例数据目录的 `mcp-tool-catalog.json` 保存最后一次工具名称、描述、排除标记、时间和截断标记。重启后立即显示数量及详情，状态保持 `unchecked`，详情标明“上次获取”和“使用时连接”。缓存为空时也不声称当前服务没有工具。
- 有缓存时，App 页面、能力弹层、设置表格不自动探测。手动刷新保留旧清单直到成功；刷新失败显示错误并保留最后一次成功结果。成功返回空清单则替换旧结果。
- MCP 内置工作区只负责状态、检查和工具展示；顶部 App 设置路由打开统一配置编辑器，不在工作区保留第二份连接设置。打开页面不会启动服务；“检查服务”成功后才显示工具详情，保存配置仍自动验证服务。
- App 卡片使用与版本信息一致的紧凑文字、图标及无边框按钮；能力入口、会话选择器、设置表格共用清单判断。

## 执行边界

持久缓存仅供展示，不存凭据、连接配置、参数 schema、调用参数或结果，也不恢复执行连接或授权。每个服务最多 200 个工具，文件最多 512 KiB；损坏或过大的文件按无缓存处理。缓存按 App 版本、服务配置版本和启用状态匹配，更新配置、移除/重建服务、清除授权后不会继续使用旧结果。写入失败不影响真实调用。

Agent 的 schema 缓存仍由运行时独立管理。使用缓存描述符或重新连接时，真正发出 `tools/call` 前重新获取 `tools/list`，每个连接的并发请求合并为一次；重新连接会再次获取。新目录同时更新运行时 schema 缓存和 Desktop 展示。当前连接的 `tools/list_changed` 通知仍按既有流程处理。此刷新会有一次真实连接/取目录的等待，不是界面要求的手动刷新。

运行时目录更新通过进程内订阅传给 App Host。Host 核对实际启动配置、会话工作目录、服务版本及当前授权，并拒绝配置或授权重置前的连接迟到结果。展示缓存不会让停用或未授权服务获得调用权限。

## 验证

42 项 Host、能力摘要、选择器和真实 MCP 生命周期测试通过，覆盖重启恢复、配置及授权失效、坏缓存、失败保留、成功清空、并发检查合并、迟到结果与首次调用刷新。UI 与内置页通过 TypeScript 检查，Desktop 运行模块、Renderer 和内置页构建通过。

`moss-apps/scripts/verify-app-capabilities.mjs` 在隔离 Electron profile 的实际 EmbeddedAppView 中连接 Excel MCP，验证 42 个工具、重启缓存、打开详情无额外检查、手动刷新以及停用状态。实际会话选择器验证键盘选择、搜索、移除和会话隔离。

完整 Desktop 的 `ui/tests/mcp-app.electron.mjs` 验证 Draw.io 的 8 个真实工具、打开时不连接、手动检查、设置保存、连接失败恢复、工具筛选和启停。旧测试把名称查询固定断言为一条结果；上游描述现在会引用其他工具名，改为按实际目录断言所有匹配项。

本次是 Core 源码及本地构建变更，没有更新用户已安装的 Moss 或发布 App 市场版本；不需要新增 App Manifest 字段。配套 App 头部规则见 `moss-apps/docs/app-layout-contract.md`。
