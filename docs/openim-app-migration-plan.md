## 1. 已确认的产品模型

OpenIM 是登录用户自己的即时消息客户端，不是由渠道管理员统一控制的外部机器人渠道。

假设当前登录用户是 A，联系人是 B：

- 策略由 A 在自己的 Moss 客户端配置，只决定 A 是否以及如何回复 B。
- B 在自己的客户端拥有完全独立的策略，A 的设置不会影响 B。
- A 可以设置一个默认策略，也可以为 B、C、D 等每个联系人建立完整的自定义策略。
- 默认策略是便捷模板和回退值，不是联系人策略的权限上限。
- 联系人策略可以完整覆盖回复方式、Agent、Tool、Skill、Connector、执行权限和上下文方式。
- 联系人策略最终仍不能超过 A 在 Moss Core、操作系统和组织策略下实际拥有的权限。

飞书当前采用的“实例默认策略 + 外部成员限制”模型继续保留，但不能直接套用到 OpenIM。

## 2. 策略与会话定义

### 2.1 策略作用域

首期只对单聊开放自动回复。策略的逻辑主键为：

```text
本地 Moss 用户 + OpenIM 实例 + 单聊会话 ID
```

联系人 ID 用于展示、迁移和校验；OpenIM 单聊会话 ID 是运行时权威标识。切换 Moss 账号、OpenIM 实例或联系人后必须完全隔离。

策略分为两种状态：

- `follow_default`：实时使用当前用户的默认策略。
- `custom`：保存该联系人的完整策略快照，默认策略变化不再影响它；用户可以随时“恢复默认”。

单聊联系人使用会话级 Binding，不使用飞书式的成员收窄规则。群聊后续使用独立模型：一个群对应一个共享 Agent 会话，群成员设置只控制触发条件，不拆成多个互相割裂的上下文。

### 2.2 回复方式

| 模式 | 行为 |
| --- | --- |
| `human_only` | 仅显示正常消息，不启动 Agent。 |
| `ai_draft_review` | Agent 生成建议回复并放入本地审核区或输入框；批准前对方不可见，用户可编辑、发送或丢弃。 |
| `ai_auto` | Agent 完成后自动以当前用户身份发送；需要交互授权或执行失败时转入本地待处理状态。 |

单聊首期不使用 `mention_only`。群聊上线时默认使用仅 @ 触发或 AI 草稿模式。

### 2.3 每联系人 AI 配置

每个自定义联系人策略可以完整设置：

- 回复方式。
- 使用的 Agent。
- 允许使用的 Tool、Skill 和 Connector。
- 工具执行与确认策略。
- 上下文模式。
- 后续可增加消息聚合等待时间、自动回复冷却时间和连续自动回复上限。
- 后续可增加联系人专属回复要求，例如语气、语言和业务边界。

资源选择是当前用户可用资源集合内的完整选择，不与默认模板做交集。Core 在执行前仍要再次计算安全上限，并拒绝未安装、未授权、已停用或越权资源。

### 2.4 会话与自动压缩

默认采用“每个单聊一个长期逻辑会话”：

```text
A ↔ B → Agent Session B
A ↔ C → Agent Session C
A ↔ D → Agent Session D
```

- 同一联系人收到和发出的消息按顺序进入对应上下文。
- Moss Core 负责自动压缩历史，联系人到逻辑会话的映射保持不变。
- Core 可以在内部执行物理 Session 轮换，但必须携带可信摘要，对用户表现为连续会话。
- 设置页提供“重置 AI 上下文”，创建新的物理 Session，同时保留旧 Session 和审计记录。
- 可提供“每条消息独立”作为高级隐私模式，但不作为默认值。
- 关闭 AI 不删除上下文；首期不会把关闭期间的消息隐式补入 Agent 历史。

## 3. 运行与安全规则

- 外部消息始终是不可信输入，不能成为 system/developer 指令。
- AI 使用的是当前登录用户的身份和资源权限，而不是联系人的权限。
- 自动回复默认只允许显式授权且无需临时确认的操作；遇到确认请求时暂停并转为本地待处理。
- 同一单聊严格串行执行；连续短消息聚合作为后续 P2。
- 用户开始输入或主动发送时，人工操作优先，尚未投递的自动回复必须暂停或取消。
- AI 生成、系统通知、撤回、已读等事件不能再次触发 Agent，避免回复环路。
- 来源消息 ID、Agent Turn 和 OpenIM 发送结果必须幂等关联。
- 断线重连只处理水位线后的实时消息；超过允许时间的历史未读消息不得批量自动回复。
- 草稿在批准前不能向联系人发送“AI 正在等待确认”等外部提示。
- App 不取得 Moss 登录 Token、模型密钥或 Connector 密钥；只获得用户选择、截图或 App 私有缓存中的受控文件路径。

## 4. 组件边界

### Moss Core 保留

- 当前 Moss 身份、组织目录和安装授权。
- Agent、Session、Turn、历史压缩和取消。
- Tool、Skill、Connector 目录及最终权限裁决。
- 联系人策略、逻辑会话映射、草稿状态和最小审计记录。
- Credential Vault、受限文件/媒体句柄及系统权限 Broker。
- App 安装、升级、回滚、禁用和卸载能力。

### `moss.openim` App 所有

- OpenIM 登录、SDK 生命周期、连接与重连。
- 通讯录、会话列表、聊天详情和消息渲染 UI。
- OpenIM 消息事件转换、发送、撤回、已读和平台错误处理。
- 联系人 AI 策略入口、草稿审核交互和 AI 状态展示。
- OpenIM 专属媒体格式、群聊、名片、位置和 RTC 交互。
- OpenIM 本地缓存及可重建索引。

### Moss Server 保留或代理

- Moss 登录鉴权及组织边界。
- 当前 OpenIM 账号供应、Token 签发、用户映射和群创建的权威校验。
- 不保存桌面端的联系人 AI 策略。
- 首期 Agent 在 Desktop 执行，因此只有桌面在线且登录时才会自动回复；未来如需 7×24 小时回复，再单独实现 Server Agent 执行链和策略同步。
