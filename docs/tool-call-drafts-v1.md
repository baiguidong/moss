# 工具调用草稿 · 第一版

用户确认的范围：只做宿主用户设置，不扩展 App Manifest、SDK 草稿声明、全局工具或专用全局提示词。

## 使用流程

在「插件 → 常用 → 打开 App → 工具」中，每行工具右侧选择「正常调用」或「草稿确认」。默认为正常调用，沿用原有权限；App 和 MCP 使用相同体验。配置保存在用户数据目录，签名包和第三方代码不变。

用户在主会话提出需求，模型照常调用原工具。Core 完成普通权限检查后，宿主根据工具原始身份查询用户设置。需要草稿时暂停该次调用，在主会话显示实际参数。用户可以修改参数、保存、确认执行或取消。确认后的真实工具返回值继续交给原会话。待处理工作台关联原会话，业务操作草稿页保留汇总入口。

工具返回不等于业务成功：返回令牌、业务确认要求或其他内容时，卡片只显示「工具已返回」及原始结果，模型继续处理真实工具返回。第一版不做 QQ 邮箱专用令牌消费。

## 执行约束

- 按用户、App、原生 contribution ID 或 MCP 实例/服务/工具名存储策略，不根据别名和自然语言判断。
- 草稿绑定参数、Schema、App 版本、工具/服务配置摘要、原会话与 tool-use ID。更改参数需通过 Schema 校验，更新 revision，使旧确认失效。
- 确认前重新核对会话、App、授权及来源配置。确认时按最终参数重新走原工具权限检查。草稿无法授予额外权限，bypassPermissions 不跳过显式草稿规则。
- 确认以持久化状态抢占，一份草稿仅执行一次。取消、会话停止、超时均不会返回假成功。
- 执行后异常记为结果未知，不提供重发；MCP 草稿调用关闭 Moss 的自动会话恢复重试和 URL elicitation 重试。
- 刷新页面可以继续审核；重启 Moss 后，未执行草稿失效，执行中草稿转为结果未知。第一版不重放已经丢失的会话调用栈。
- 改回正常调用只影响后续调用，不自动执行已存在的草稿。
- 第一版作用于 Moss Agent 的结构化 App/MCP 工具调用，不覆盖任意 Shell、网页操作、App 内部自行发起的后台行为。

## 实现边界

独立用户策略存储 `app-tool-call-policies.json`；独立调用草稿存储 `tool_call_drafts.json`，通过既有草稿 IPC 汇总。原先 App 主动提议业务草稿的协议兼容保留，两种草稿使用不同执行入口。

通用表单读取工具 Schema 的字段名、标题、描述、枚举与类型。对象/数组支持 JSON 编辑，完整 JSON 编辑作为复杂 Schema 的通用入口，最终由宿主校验。

## 验收

需要覆盖用户设置持久化与身份隔离、正常调用、自动批准模式下的草稿拦截、编辑参数、旧版本确认、并发确认、取消、刷新、重启、授权/来源变化、执行异常及第三方两阶段返回。

使用不声明草稿能力的普通 App 和 MCP fixture，经真实主会话和 CDP 验证；所有效果仅记录到隔离本地数据，不发送真实邮件。


本机验收已通过：76 项定向测试、2 项真实会话运行态回归、UI check/build，以及 7 组 CDP 主流程检查。CDP 包含 App/MCP 参数编辑、取消零执行、自动批准模式下拦截、刷新、断网不重发、强制终止进程后恢复、两阶段返回不误报成功；页面异常为 0。

复现：在仓库根目录执行 `node ui/scripts/test-tool-call-drafts-cdp.mjs`，需先构建 Direct Runtime 与 Renderer。脚本使用隔离用户目录、本机模型与 MCP 服务，不连接真实邮箱；证据位于 `output/tool-call-drafts-cdp/`。此结果不代表全仓测试全绿。
