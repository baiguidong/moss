# 设置 App 自带 UI 的迁移实现

2026-10-29；Host API 3.22.0。

Core 根据 App 配置统一展示介绍、基本信息、授权、技能、MCP 服务和缓存工具。带 UI 的 App 在顶部“试用”旁统一提供“打开”，点击后进入占满内容区的 App 工作区。详情不再逐项展示“系统权限与控制”等业务页面入口。多个声明页面按配置中的声明顺序在工作区顶部切换，默认打开首个可访问页面；单页只显示 App 名称和返回入口。Core 表单、技能说明和普通 MCP 连接设置仍使用右侧面板；普通 MCP 不显示 App UI 的“打开”。

## 配置与桥接

```json
{
  "hostApi": "^3.22.0",
  "navigation": { "location": "details" },
  "ui": { "entry": "dist/ui/index.html" },
  "contributes": {
    "views": [{ "id": "connections", "title": "数据库连接", "route": "#/" }],
    "settings": [{
      "id": "manage", "title": "数据库连接", "group": "integrations",
      "viewId": "connections", "presentation": { "width": "wide" }
    }]
  }
}
```

`form` 与 `viewId` 仍互斥，不同设置项可以混用。`presentation.width` 保留兼容，App 整页工作区不再依赖面板宽度。旧 `settings`、`more` 和 `none` 声明及直接路由保留；插件卡片统一先打开详情，顶部入口按声明解析真正的 App 页面。新版本详情导航不再列入全局设置。

桌面和 Web 均按设置 ID 与安装版本打开，由 Host 解析声明路由并检查设置及视图权限。更新、停用、撤权会使旧页面失效。页面使用原有隔离会话、凭据与主题桥接；Core 不读取 App DOM，不按 App ID 判断。

App 通过 SDK `view.setState({ dirty, busy })` 上报页面状态。未保存时离开需确认，提交期间阻止关闭与导航。调整窗口尺寸保留同一个页面及输入。切换页面同样检查未保存/提交状态；返回详情时清理页面请求、事件订阅和轮询；已被 Backend 接受的自测任务继续运行。

## 迁移范围

| App | 版本 | 入口及保留功能 |
| --- | --- | --- |
| MCP 管理 | 0.1.15 | 管理服务：多服务增删改、启停、凭据、OAuth 和主动检查 |
| 数据库查询 | 0.2.3 | 数据库连接：数据库类型、只读策略、行数上限、凭据及增删改；保存与测试分开 |
| 记忆 | 0.2.5 | 记忆图谱：实体、关系、筛选、搜索及存储位置 |
| 电脑操控 | 0.2.3 | 系统权限与控制：系统授权、已授权应用、启停与停止控制 |
| 飞书 | 0.4.15 | 连接与配对、执行权限；进入 App 后按声明的真实路由切换两个页面 |
| AI 自测 | 0.1.21 | 自测工作台：项目选择、执行/停止、测试实例、进度及报告 |

六个包移除了重复通用设置注入、介绍和工具列表。历史排除工具配置仍保留，页面不提供编辑入口。数据库只读、电脑控制授权和飞书执行权限属于业务功能，继续保留。

MCP 管理不再自动发现工具。记忆 Backend 启用时仅注册固定服务，图谱直接读本地文件；浏览、保存及重新启用不连接 MCP。工具清单继续由 Core 读取当前版本缓存，升级不显示旧版本目录。主动检查或实际使用才连接。飞书原有长连接和自测后台任务遵循各自生命周期。

## 验证

- Core 类型及导出契约检查；`app-settings-view`、`app-navigation`、`app-details`、`app-manifest-v2`、`app-sdk-types` 测试。
- `web-adaptations.test.mjs` 验证声明路由、所属用户、绑定的页面状态、撤权失效及清理。
- `app-settings-views.electron.mjs` 在隔离 Profile 安装六个迁移包及审计中心独立工作台，验证详情无嵌入页、顶部点击后进入整页、正确路由及多页切换、调整窗口不重建、未保存/提交保护、主题和窄窗口；MCP 检查计数保持为零。截图与报告位于 `output/app-settings-views/`。
- App 包执行各自类型检查、业务测试及构建，包含固定源码快照；电脑操控沿用可信发布者签名，不修改用户信任配置。
- 数据库验证真实 SQLite 的连接增删改、密码不回显、只读限制、行数上限及重启恢复；MCP 验证真实 stdio/HTTP/SSE、凭据和启停；记忆验证九个工具、离线运行、并发写入、图谱与持久化。

飞书配对/解绑和自测生命周期由业务测试覆盖；迁移验证不发送真实飞书消息、不调用用户模型运行整轮自测、不操作用户桌面目标应用。安装更新保留原 App 身份、数据、凭据与授权，需重启 Moss 加载新的 Core 和原生版本。

2026-10-29 的入口与布局调整仅修改 Moss Core；沿用以上 App 包和配置，不需要重新打包 App。
