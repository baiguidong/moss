# Moss 运行中补充与侧问

按用户最新反馈，移除“补充当前任务 / 下一轮发送 / 侧问”的发送方式选择。主输入框始终使用“发送”，侧问按钮放在主输入框底部，打开应用内独立浮窗。Workspace、Task list、Boss/Team、文件观察及原有草稿恢复机制保留。

## 当前交互

- **主会话发送：**运行中的消息默认补充当前任务，在当前回复完成或本批工具回执全部返回后进入上下文；不强行中断工具或在途模型请求。
- **附件、Skill、Agent：**附件按主会话现有机制准备成文件引用，App 文档引用由 Host 解析，Skill 与显式 Agent 复用原有指令构造和目录校验，然后一起补充当前任务。UI 显示原始文字和附件，不展示生成的内部指令。
- **自动衔接：**任务尚未准备好接收、刚好收尾，或消息涉及模式切换、App 资源工具加载、斜杠/shell 命令时，由系统保留完整消息并安排后续执行。此类操作仍需等当前运行结束后重建执行环境，客户无需选择发送轮次。只有 Host 明确未接收时才采用此路径；网络回执未知时保留输入，不自动重发。
- **侧问：**点击主输入框底部“侧问”，在浮窗自己的输入框提问。回答单独显示，可以折叠；收起浮窗保留草稿和答案，正在回答的侧问继续运行。取消侧问不停止主任务。仍支持在主输入框发送 `/btw 问题` 自动打开浮窗。
- **位置：**浮窗随主输入区高度调整位置，避开主输入框和发送按钮；窄窗口中限制宽高，答案区域独立滚动。侧问不会占用右侧文件预览或结果面板。

侧问有自己的输入状态，发送、失败或取消均不清空主会话的文字、附件、Skill、App 选择。收起后可再次打开继续查看本会话的侧问记录；侧问答案不进入主模型历史，每次提问基于当时的主会话快照独立回答。

## 实现与边界

Core 为每个前台 QueryEngine 持有独立 `TurnInputQueue`，在工具回执收齐后及无工具回复结束时接收补充。补充关联原任务用户消息 ID，避免重复文件变化卡。子 Agent 不继承此入口。

Host 的 `agent:session-interaction` 绕过主发送的串行队列。准备附件期间按请求 ID 去重；准备完成后再次检查运行时、任务 ID 和忙碌状态，避免插入替换后的任务。取消时完整消息详情保留，可恢复为草稿；界面中只保留简短的等待/取消提示。

UI 侧问使用独立的无工具模型请求，不运行主查询循环、Hook、工具执行器或自动压缩；也不写入主 JSONL。为兼容提供方，历史工具请求/结果转换为可读副本，未收到结果的工具明确标为完成状态未知。独立取消信号、120 秒超时、4096 输出 token 和 32 KB 展示上限沿用上一批实现。

入口适用于 Desktop/Web Host 的本地会话。侧问要求当前运行时已经建立主会话模型上下文；远端旧协议未扩展。CLI 原 `/btw` 路径保留。本批没有复刻 Claude 的完整缓存内部实现，也不保证跨进程崩溃的恰好一次执行。

- 68 项回归通过：原队列撤回/草稿、主会话分组、文件观察、Host 接收去重与准备阶段竞争、自动衔接、附件和技能准备、原始用户内容展示、主草稿与侧问隔离。
- Electron 实际 React 界面：原队列 5 组、新交互 4 组通过，验证底部入口、取消、收起后草稿保留、`/btw`、附件补充及浮窗不遮挡主发送控件。检查了 520 px 和 1120 px 截图。
- 实际打包 ClaudeSession + 本地 HTTP fixture 通过：主工具挂起时侧问先返回；两项工具回执之后插入一次含附件和 Skill 指令的补充，下一次模型请求确实包含它；并行会话隔离、独立取消及主 JSONL 持久化仍正确。
- UI 完整检查与 renderer 生产构建通过。此轮未修改 Core；上一批根目录 tsc 的历史问题仍然存在，不报告为全仓类型检查通过。
