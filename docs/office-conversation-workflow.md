# 主会话文档工作流：引用、局部修改、对比与核验

2026-10-29。Excel 实时控制暂缓。创作仍在主会话完成，右侧负责原文定位、作品阅读和修改对比；不增加 App 独立工作台。App 源码和内置包仍由相邻的 `moss-apps` 仓库维护。

## 已实现

| --- | --- | --- |
| 原文引用 | 模型读取 `*_inspect` 返回的 `citation.displayMarkdown`，在回答中引用；用户点击后右侧定位并高亮 | PDF/PPT 页码、Word 引文、Excel 工作表及单元格区域；同一引用可反复点击，重开保留后续阅读位置 |

## 宿主与 App 的分工

宿主识别引用片段 `#page=2&text=...`、`#text=...&occurrence=2`、`#sheet=...&range=B12:C14`。引用先拆成真实文件/资源 URI 和位置；片段不传给 App provider，也不成为实际文件名。已有代码行号引用保持原逻辑，文件名含字面量 `#` 仍支持。

资源身份使用不含片段的真实来源；重复引用只更新位置请求，避免一个文件重复注册。读取失败、页码不存在、文字未找到、工作表不存在及区域超出已用范围均有明确提示。PDF.js 负责分页与文字层，Excel 区域引用切换到工作表视图，并为较远的单元格显示有限大小的上下文窗口。

App 在 `creation-source.json` 之外保存内容索引、结构对比和逐页核验记录。对比资源是 `moss.document-comparison/v1` JSON，通过 provider 的 `presentation.type=document-comparison` 请求宿主通用展示；用户看到修改前后内容，不需要阅读 JSON。普通作品资源携带版本、核验状态和对比 URI，宿主在原有右侧展示统一入口。

PPT 对象按演示文稿关系文件中的实际幻灯片顺序读取。对象定位同时包含原生 ID 和对象顺序，兼容本地 PptxGenJS 生成同页重复 ID 的实际情况。编辑直接修改目标 OOXML 部件，不重建整份文件；更换图片创建独立媒体关系，避免改变其他共享同一图片的对象。Word 修订保留原有文字样式和原生修订标记。

## 核验含义与边界

- 程序检查覆盖可解析内容、PPT 页面越界/小字号/空图表系列、Excel 错误值等。渲染成功与视觉检查完成是不同状态。
- `verify` 的 `observations` 和 `issues` 来自执行任务的模型。宿主核对版本、页码和完整性，但不能据此证明模型确实看过图，也不把程序检查等同于视觉理解。技能要求先用可用图片工具读取实际页图，修复后查看新版本，连续修复最多三轮；无法解决时明确剩余问题。
- 纯阅读和原文问答不要求执行生成物的完整核验流程。只读取文件不会创建无意义的修改对比。
- 对比是已解析内容与对象属性的结构对比，不是 Word/PowerPoint 的逐像素视觉差异。大量修改有数量和体积上限，界面明确标注截断。
- Office 完整页图仍依赖本机 LibreOffice 和 Poppler，复杂版式可能与 Microsoft Office 不同。PDF App 使用包内 PDF.js 提取原文，不要求额外安装 `pdftotext`；文档 App 输出 PDF 的结构文字检查若缺少 `pdftotext` 会明确降级，仍可交给 PDF App 检查。
- PPT 支持单一二维柱形/折线/饼图的类型修改；复合图表、外部图表、共享图表、组合对象、继承母版且缺少本地位置的对象等明确拒绝。没有把不支持的内容用截图替换。
- Word 跨超链接、复杂字段等结构的修订会拒绝；文字层缺失或布局阅读顺序不一致时，引用可能需要按页核对。没有 Excel 实时控制或在线 Office 连接。

## 第二轮优化（2026-10-29）

- Word 对比以内容序列对齐，插入或删除段落不再把后续段落逐一计为改动；重复段落保持顺序。中等文件使用最长公共子序列，大文件用有序锚点限制内存。非常大的重排或大段同时重写仍可能被呈现为新增/删除。
- 内容对比高亮具体文字变化；PPT 表格只列有变化的单元格。PPT 嵌入的 PNG/JPEG/WebP/GIF 保存到作品目录，右侧按需读取修改前后图片；不支持的图片格式保留原文定位入口。长文本与详情截断有单项提示。
- 检查结果保留原文位置，可在右侧点击定位页码、文字或工作表单元格，列表折叠后继续使用原有局部标注。核验已失效时明确说明旧记录不适用于当前文件。
- 默认只生成首批 8 页核验图，完整 PDF 可先供右侧阅读。`*_verify({id,sourceSha256,render:{startPage,count}})` 生成指定批次，count 为 1–20；省略 startPage 从第一张缺失页继续。返回 `nextRender` 可直接继续调用。生成和核验分开调用，先查看图像后再记录观察。
- 每完成一页就原子保存状态；重启、失败或超时后保留完成页，重新检查缓存文件是否存在。页图每批预算 45 秒、单页最多 30 秒，首次 Office 转 PDF 单独最多 120 秒。不能承诺转换阶段本身能断点续跑；页图续跑会复用完成的 PDF，源文件变化时拒绝复用。
- 右侧复用与源文件哈希匹配的 App 页面 PDF，避免重新调用 LibreOffice。源文件外部变化后不复用旧 PDF。批次结束后可通过 `moss_present` 或重新打开成果获取最新进度。完整页图不等于模型视觉核验完成。

新增回归包含真实 DOCX 插入段落、重复段落、3,000 段对齐、PPT 嵌入图片替换、真实 105 页 PDF 的尾页生成、中断后缺页续跑、图片缓存丢失、原文件变更拒绝复用。CDP 检查文字与表格高亮、图片对比、问题定位后局部标注、首批进度以及续跑后仍未核验的状态。仍使用隔离配置和本地模型回复夹具。

## 第三轮：升级、显示与实时状态（2026-10-29）

- 内置 App 启动同步会升级来源为 builtin、内容校验完整且版本落后的安装；保留停用状态、权限、工具作用域、实例与用户文件。手动卸载、本地创作/修改、市场安装、较新版本及用户回退的版本不会被覆盖。校验或激活失败保留原版本并允许后续重试；回退同时核对安装修订号，避免覆盖并发操作。
- 升级继续使用宿主的不可变版本目录、安装验证与条件回退。支持写时复制的文件系统在暂存安装包时复用磁盘块，其他文件系统回退到普通复制；源文件与安装副本仍彼此独立。
- Excel 工作表分别保存原始数值、显示文本和公式，按文件格式展示百分比、日期及金额。零值、false、空字符串、错误值和无缓存公式有回归覆盖；无缓存公式显示公式本身。点击单元格可查看其地址与公式。
- 工作表解析与 PDF 转换独立完成：先就绪的内容可立即阅读，背景转换完成后不强制切换用户视图。已有 PDF 不等待工作表解析，也不重复转换；切换文件丢弃旧请求的迟到结果。
- 宿主每两秒检查当前可见的 App 成果状态，隐藏页面、已关闭预览及后台会话不发起此轮询。批次生成或核验提交完成后，右侧自动更新，无需模型再次调用 moss_present。没有变化不写入展示状态；状态更新不改变原文件 revision、页码、缩放或选区。
- 修复 macOS 路径别名导致重启后页图缓存失配的问题：真实路径识别兼容历史 /var、/private/var 与目录符号链接，续跑复用先前页面。

受共享渲染修复影响的内置包：文档 0.4.3、PDF 0.3.3、表格 0.2.3、演示文稿 0.3.2、模板 0.2.2。没有修改工具加载通用规则。

验证入口：`bun run test:office-delivery`（真实 XLSX 解析及 React/PDF.js，受控异步转换）；`node --test tests/builtin-upgrade.integration.test.mjs`（真实注册表与运行时安装/回退）；`bun run test:office-workflow`（真实 Electron 与已打包 App）。后者追加 `--live-model` 可使用本机已配置文本模型，在隔离配置与测试文件上执行预算表修改验收，输出不会记录 API key。线上验收结果单独写入 `output/office-delivery/live-model.json`，不能用模拟模型结果替代。

### 测试实例底部输入区（2026-10-29）

修复 Office CDP 脚本使用 `page.setViewportSize` 后，网页按 900px 高度排版、Electron 实际内容区仅约 778px，导致输入框与底部按钮被原生窗口裁切的问题。虚拟视口截图可能包含窗口外的部分，不能作为完整可见的证据。
