# Moss Server 管控技能与专家 · 第一版

## 用户怎么用

管理员在 Moss Server 的系统设置中打开「启用服务端技能/专家管控」。开关默认关闭。关闭时，桌面端沿用原有公共 Hub、本地资源和安装方式。

管理员在 `/admin/managed-resources` 从公共 SkillHub、ExpertHub 下载安装包，或直接上传 ZIP。包保存在 Moss Server。管理页分为「技能」「专家」两个一级标签，各有「已安装」「用户授权」「市场」三个二级标签。管理员在「已安装」上传、启停或移除资源，在「用户授权」查看当前用户，或按姓名、邮箱和部门筛选多人后批量勾选资源，在「市场」搜索并安装。批量保存只调整本次变更的资源。按部门筛选时包括子部门现有用户，授权仍按用户保存。开启管控后，未分配的用户清单为空。

客户端登录后从 Moss Server 获取本人的清单和包，复用现有技能、专家页面，在本地运行。管理员登录桌面端时也遵循本人的分配结果。市场目录、安装包及图标均由服务端获取，客户端只需能访问 Moss Server。

## 一个验收例子

服务端有 12 个已启用的技能。管理员给 A 勾选其中 10 个，给 B 勾选另外 2 个。A 原先在电脑上装过全部 12 个。

1. A 登录并打开技能页，只显示分给 A 的 10 个。创建项目、选择技能和会话调用也只能使用这 10 个。B 登录同一台电脑，只能使用 B 的 2 个。
2. 管理员停用其中一个已分给 A 的技能，或取消对 A 的勾选。A 下次刷新目录或发起下一轮会话时只能使用剩下的 9 个。本地原有文件保留。
3. 客户端断开公网，保留与 Moss Server 的连接。A 仍可取得授权清单、下载缺少的包并运行。管理员可以在公共 Hub 不可达时上传 ZIP，也可以管理已安装资源。
4. 管理员关闭总开关，客户端下一次刷新恢复原有模式。以上规则同样适用于专家。

## 实现约定

- **服务端**保存资源、ZIP 和摘要，统一按「已启用且已分给当前用户」过滤清单和下载。客户端只需要当前用户清单和包下载接口。管理操作使用 Moss Server 管理身份。
- **客户端**在打开目录和会话使用前确认开关与清单，按需补齐缺少或摘要变化的包。托管包写入独立缓存，校验成功后才进入可用目录。资源查找与调用都使用同一份已确认清单。
- **网络边界**是客户端能访问 Moss Server。已知开启管控时，连不上 Server 或身份失效就暂停托管资源，重连后重新取清单。同一账号上次确认开关关闭时，暂时断开 Server 仍可使用原有本地模式。新账号首次确认开关前暂停使用技能和专家。
- **资源范围**为 Skill 与 Expert。第一版使用按用户勾选的允许清单。角色和部门继承、独立审计系统、其他类型资源的管理均留到后续。

## 旧方案的处理

- 移除桌面端的管理分支和公共 Hub 镜像代理。导入、上传、启停、移除和用户授权统一在 Moss Server 后台完成。
- 移除允许、拒绝、继承三种策略的编辑和运行逻辑。读取旧数据时，把已保存的策略按当时的资源库换算成具体资源 ID。以后新入库的资源需管理员勾选后才对用户开放。
- 移除靠资源目录版本号判断授权的设计。刷新时直接取当前账号清单，使用包摘要判断是否需要重新下载。客户端保留个人安装目录，切回本地模式后继续使用。第一版省去离线授权租约和推送服务。
