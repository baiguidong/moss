# moss-server 控制台菜单与权限梳理（第一版）

## 本次 UI 调整

- 登录页统一为 Moss 控制平面品牌：`moss` M 图标、浅灰绿色背景、深绿色主色、圆角卡片和更清晰的登录主按钮。
- 内部页面统一使用同一套页面壳层：品牌侧栏、工作区/管理分组、内容区背景、页面标题层级和卡片间距。
- 根路由改为独立“工作台”。工作台只展示组织摘要、个人今日用量和工作电脑状态；“工作电脑”保留设备控制、任务明细、企业策略和定时任务。
- 侧栏补充“API Key 管理”，并按 `admin:api_keys` 权限显示。

## 菜单保留建议

| 菜单 | 当前路由 | 保留理由 | 可见权限 |
| --- | --- | --- | --- |
| 工作台 | `/` | 统一入口，避免把数据摘要和设备管理混成一页 | 登录用户 |
| 工作电脑 | `/computers` | 设备在线状态、任务控制、企业电脑策略有独立管理价值 | `sessions:list` / `sessions:list:any` |
| 用户与组织 | `/users` | 用户、部门、角色、组织知识库状态集中维护 | `admin:users` |
| API Key 管理 | `/api-keys` | 凭据生命周期需要单独入口，避免埋在用户详情中 | `admin:api_keys` |
| 系统设置 | `/settings` | 模型、空间、即时消息等组织级配置 | `admin:settings` |

## 建议合并或下线

- 原“数据看板”不再作为设备列表别名；已拆成工作台摘要 + 工作电脑详情。
- “个人用量”不再占用顶层菜单，保留为工作台快捷入口和用户详情入口；完整趋势页仍可通过 `/usage` 访问。
- `/sessions` 继续保留兼容重定向到 `/computers`，避免旧链接失效；服务端执行会话接口已经明确返回 410，不应再做新菜单入口。
- 用户页中的 RAGFlow 服务状态保留在组织管理上下文中；凭据操作只对具备 `ragflow:credentials` 的管理员显示。
- API Key 创建和撤销继续保留；权限选择应只来源于当前操作者可委派的权限，不能把受保护的 `admin:roles` 暴露为普通自定义角色能力。

## 权限核对结果

- `admin:roles` 是受保护权限，服务端通过 `requireSystemAdmin` 控制，不能分配给自定义角色；UI 角色管理也只对系统管理员开放。
- `hosts:report` 是工作电脑内部上报权限，不应出现在用户角色或 API Key 的普通授权面板。
- `sessions:terminate:any` 在会话控制代码中被使用，但当前权限目录没有对应定义；建议下一版补充目录项，或者确认它是否应由 `admin:users` 统一覆盖后移除独立判断。
- `ragflow:credentials` 只用于查看/轮换个人知识库凭据，属于高敏能力，建议继续保持管理员专用并记录审计。
- `directory:read`、`im:use`、`im:group:create`、`agent-mail:*` 和 `cloud-storage:*` 由客户端/业务接口使用，不属于当前控制台的顶层菜单权限，不建议为了“菜单完整”新增对应页面。
- 部门管理员目前继承 `admin:users`，服务端会按所属部门及子部门过滤用户；角色管理和组织级设置仍由系统管理员控制。

## 下一步建议

1. 补齐 `sessions:terminate:any` 的权限目录与角色矩阵，明确它和 `admin:users` 的边界。
2. 给菜单权限和页面关键操作补一组低权限回归用例：普通用户、部门管理员、系统管理员各走一遍。
3. 如果后续需要更细的运营报表，再单独新增“组织用量”页面，避免把个人用量和工作台再次耦合。
